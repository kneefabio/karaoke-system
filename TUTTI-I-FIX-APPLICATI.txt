Ho identificato e risolto 2 BUG CRITICI che impedivano il login:


🐛 BUG #1: ENVIRONMENT VARIABLES IGNORATI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEMA:
   Backend su Render ignorava le variabili d'ambiente configurate
   nel dashboard e cercava di connettersi a localhost:27017

CAUSA:
   server.py linea 21 caricava SEMPRE il file .env locale:
   load_dotenv(ROOT_DIR / '.env')

SOLUZIONE APPLICATA:
   Rilevamento automatico dell'ambiente:
   
   if os.environ.get('RENDER'):
       # Produzione: usa variabili Render
       pass
   else:
       # Sviluppo: carica .env locale
       load_dotenv(ROOT_DIR / '.env')

RISULTATO:
   ✅ Su Render → Connessione a MongoDB Atlas
   ✅ In locale → Funziona come prima


🐛 BUG #2: PASSWORD BYTES ENCODING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEMA:
   Login crash con:
   AttributeError: 'bytes' object has no attribute 'encode'

CAUSA:
   Il codice tentava di fare .encode() su password già in bytes:
   admin['password'].encode('utf-8')  ← già bytes!

SOLUZIONI APPLICATE:

   1. Login endpoint (linea 313):
      PRIMA: admin['password'].encode('utf-8')
      DOPO:  admin['password']

   2. Change password check (linea 572):
      PRIMA: admin['password'].encode('utf-8')
      DOPO:  admin['password']

   3. Password storage (linea 588):
      PRIMA: update_data['password'] = hashed_password.decode('utf-8')
      DOPO:  update_data['password'] = hashed_password

RISULTATO:
   ✅ Login funzionante
   ✅ Cambio password funzionante
   ✅ Password salvate correttamente come bytes
